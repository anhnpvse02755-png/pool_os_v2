# RFC-KB-002 — Knowledge Pack V1 + Beta Knowledge Experience

## Context

Tasks 1–15 are complete; Coach V2 (Task 15) is the decision-making center that
emits KnowledgeIds resolved via a registry. RFC-KB-002 makes **Knowledge** a
first-class product asset, shippable in Release 1.x *before* any CMS exists.

Two objectives:
1. **Author a real Knowledge Pack V1** — original, synthesized pool coaching
   content (techniques, common mistakes, equipment, mental, strategy), each item
   on one strict schema, with a status (Verified/Beta/Draft), difficulty, a
   knowledge graph, and Coach trigger metadata. CMS-ready format so the source
   can later switch bundled assets → Knowledge API with no UI change.
2. **Beta Knowledge Experience** — expose Knowledge now: a usable **Learning Hub**
   surface, a KnowledgeDetailScreen, Verified/Beta/Draft badges, a "Coach
   recommends this" banner from Coach, media placeholders ("coming soon"), and
   feedback (helpful? / suggest / report) with no backend.

### Hard constraints (frozen)
- No CMS, no backend, no API, **no DB changes**, no Flutter architecture changes,
  no AI implementation, no generated media.
- Real content, honestly marked as evolving (Beta) — "no fake completeness".
- Coach only returns a KnowledgeId; the Learning Hub decides display.
- Original synthesis (Dr. Dave, Tor Lowry, Sharivari, WPA, pro/VN methodology) —
  NOT copied text/articles/video. Vietnamese-first, technically accurate.

## Terminology (frozen — one name each)
- **Learning Hub** = the surface (evolved Training Center). NEVER "Knowledge
  Browser". Hierarchy: Coach → Learning Hub → Knowledge → Drill.
- **KnowledgeItem** = the single model class. NEVER also called
  "KnowledgeArticle".
- **Coach Data Confidence** = how much/what data Coach has to judge the player.
  NEVER "Knowledge Confidence". Distinct from per-insight Recommendation
  Confidence (Task 15).
- **Drill is NOT a Knowledge type.** DrillLibrary is the single source of truth
  for drills; Knowledge only *references* drills via drillRefs.

## Exploration findings (confirmed)
- DrillLibrary (lib/features/drill/data/drill_library.dart, 1272 LOC) =
  hardcoded Dart catalog, 17 DrillCategory codes; Drill has fromJson/
  getDrillByCode. STAYS UNCHANGED = the "Built-in Drill Repository".
- training_center (Task 09) is the LIVE surface: reads DrillLibrary via
  TrainingDrill + libraryByCategoryProvider; /training-center route with
  ?category= deep-link (Task 15). CategoryDrillsScreen lists a category.
- drill_detail_screen.dart (709 LOC) = sectioned layout + gradient/category-icon
  header — the media-placeholder pattern to reuse; its ROLE is superseded by
  KnowledgeDetailScreen (leave file, stop routing to it — flag in PR).
- Coach seam (Task 15): knowledge_registry.dart maps a KnowledgeId → drill
  category/route; coach_screen.dart deep-links /training-center?category=….
- **No url_launcher/share_plus** in pubspec (deps: riverpod, go_router, drift,
  fl_chart, intl, uuid, lucide_icons). Clipboard (flutter/services) needs none.
- **No asset-bundle loading anywhere** yet; pubspec.yaml flutter: has no
  assets: entry — must add one. jsonDecode widely used.

## On-execution doc edits (first, once out of plan mode)
- Append to RFC-KB-002.md: "Release 1.0 is not the final Coach. It is the first
  public Coach capable of analyzing real player data, recommending training, and
  delivering structured knowledge. Community feedback collected during this
  release will continuously improve the Knowledge Pack and Coach recommendations
  in future releases."
- Create RFC-KB-002 Review Feedback.md (the user's review text) and
  RFC-KB-002 Final Update.md (the final-review text).

## Implementation plan

### A. Knowledge domain — new root feature lib/features/knowledge/
domain/models/knowledge_item.dart — the single KnowledgeItem schema:
- **Identity/taxonomy:** semantic string id (e.g. tech.stop.basic,
  mistake.lifting_head, equipment.tip.soft, mental.pressure,
  strategy.pattern.beginner), type, skillId (maps to Coach skill
  categories), parentId? (nesting: Cue Ball Control → Stop Shot → Level 1/2),
  category, difficulty, status, title(+vi).
- **Content:** summary, purpose, prerequisites, setup, execution,
  successCriteria, failureCriteria, commonMistakes[], corrections[],
  coachNotes, keywords[], estLearningMinutes, media{video?,gif?,animation?,
  diagram?} (paths only; no media generated).
- **Graph (single scheme):** relatedKnowledge: List<KnowledgeRef> (edges to
  other KnowledgeItems) and drillRefs: List<String> (DrillLibrary codes —
  drills are referenced, never embedded). There are NO
  relatedDrills/relatedTechniques/relatedEquipment fields and NO separate
  drillRef vs relatedDrills duplication.
- **Coach/recommendation metadata:** coachTriggers[], nextRecommended?
  (KnowledgeRef — learning path "Next"), recommendedFor: List<String> (player
  levels/ranks, so Coach won't push beginner content to advanced players),
  estimatedSkillGain: Map<String,int> (per-skill weights {skillId: 0-100},
  NOT a single number — future Coach asks "which skills does this raise?").
- **CMS-prep metadata:** knowledgeVersion (content version, separate from app
  version and from revision), revision, createdAt, updatedAt,
  verifiedBy, reviewStatus, sources[] (internal/CMS-only — NEVER rendered
  in the UI).
- Enums: KnowledgeType { technique, commonMistake, equipment, mental, strategy }
  (**no drill**); KnowledgeStatus { verified, beta, draft } (**only here,
  never on the Drill model**); KnowledgeDifficulty { beginner, intermediate,
  advanced, professional }. KnowledgeRef { id, type }. fromJson/toJson.

data/knowledge_repository.dart — loads bundled JSON from assets/knowledge/**
via rootBundle.loadString + jsonDecode (first asset-loading; Drill.fromJson
proves the pattern). Read-only, in-memory cache. API: getAll(), byType(),
byCategory(), byId(semanticId), byKnowledgeId(coachKnowledgeId),
related(item) (resolves relatedKnowledge), drillsFor(item) (resolves
drillRefs live via DrillLibrary.getDrillByCode). It NEVER copies drill
content into Knowledge.

presentation/providers/knowledge_providers.dart — FutureProviders over the
repository (all, by type, by id).

### B. Knowledge Pack V1 (real content, assets/knowledge/)
CMS-ready folders — **no drills/ folder** (drills live in DrillLibrary):
techniques/ mistakes/ equipment/ mental/ strategy/. One JSON file per item.
**Quality over quantity:** a SMALL, fully-linked, internally-consistent V1 — a
few skills built deep (e.g. Cue Ball Control → Stop Shot → levels, each with
common mistakes, corrections, drillRefs into DrillLibrary, nextRecommended,
estimatedSkillGain), mostly beta with a couple verified. Original
synthesis, VN-first. pubspec.yaml: add assets/knowledge/ to flutter:
assets:.

### C. Training Center → Learning Hub
Reframe training_center_screen.dart as the **Learning Hub** — a shell listing
*modules* (Knowledge is module #1; leave room for future Practice Plans, Warm-up,
Coach Assignments, Challenges, Certifications… without coupling to "Drill").
The Knowledge module shows a "Coach Recommended" section on top (when arrived via
?knowledgeId=), then Knowledge grouped by type/category, with a **status badge**
(Verified/Beta/Draft) on each card. Existing drill browsing via
CategoryDrillsScreen stays. Keep ?category=; add ?knowledgeId= to open a
detail.

### D. KnowledgeDetailScreen (supersedes drill_detail_screen.dart's role)
One renderer for every KnowledgeType: title, difficulty, **status badge**,
**Coach-recommendation banner** (when opened from Coach), purpose, setup,
execution, success/failure criteria, common mistakes, corrections, **related
knowledge** (tappable KnowledgeRef edges) + **referenced drills** (pulled live
from DrillLibrary via drillRefs), **media placeholders** ("Coming soon"),
**Next (learning path)** from nextRecommended, last-updated/knowledgeVersion,
and the **feedback row** + **beta message**. sources[] is NEVER shown. Reuse the
gradient/category-icon header pattern from drill_detail_screen.dart.
Route: reuse /training-center?knowledgeId=<id> (no NEW route);
TrainingCenterScreen.initState opens the detail when initialKnowledgeId is set
(mirrors existing initialCategory).

### E. Coach ↔ Knowledge wiring (Task 15 seam)
Extend knowledge_registry.dart so a technique/practice KnowledgeId resolves to
a **Knowledge item semantic id**; coach_screen.dart deep-links
/training-center?knowledgeId=<id> (opens the article with the banner). Coach
still only emits a KnowledgeId. Surface **Coach Data Confidence** in the Coach
communication (built on Task 15 CoachUnderstanding) — what is known / uncertain
/ still-missing — distinct from Recommendation Confidence.

### F. Feedback (no backend)
KnowledgeFeedback widget: 👍/👎 + "Suggest improvement" + "Report issue". Since
url_launcher is NOT a dependency, V1 uses Clipboard.setData (flutter/services,
no new plugin) to copy a prefilled template + a SnackBar "copied — paste into
<email/Form/GitHub>". (Open question below: add url_launcher vs clipboard-only.)

### G. Localization + Beta messaging
Add kb_* keys (en+vi) for badges, beta message, coach banner, media "coming
soon", feedback labels, "Next" — following the coach_v2_*/tnmt_* append
pattern in app_localizations.dart.

### Constraints honored
No DB change (schemaVersion stays 20), no new top-level route (reuse
/training-center query params), no AI, no generated media, DrillLibrary
untouched, KnowledgeStatus never on the Drill model, drills referenced not
duplicated.
