Pool OS V2 follows a 4-phase roadmap. Future work must always declare which
phase a feature belongs to.

**Why:** V1 is historical context, not the source of truth. The source of
truth is the product vision — "if this were the world's best billiards training
app, what would it need?". Comparisons against V1 are only meaningful inside
Phase A.

**How to apply:**
- Phase A — V1 Parity: no regression vs V1. Use V1 as one input, not the goal.
- Phase B — Content Expansion: drills, knowledge, learning paths, linking.
- Phase C — AI & Analytics: AI coach, technical analytics, advanced reports,
  deep statistics.
- Phase D — Competitive Features: community, tournaments, sharing, sync,
  differentiators.

When writing a gap analysis, always:
1. Start from vision (what the user deserves).
2. Layer V1 parity on top.
3. Mark each gap with a phase tag (`[A]`, `[B]`, `[C]`, `[D]`).
