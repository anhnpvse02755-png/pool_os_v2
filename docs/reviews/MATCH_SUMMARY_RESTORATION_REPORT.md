## 3. V2 Match surface

### 3.1 Match basic info

- Match ID, Date, Time, Duration, Game type, Race format, Venue, Table, Opponent, Winner, Final score — **all live**.

### 3.2 Performance

- Total racks, Win %, Breaks, Break & Run, Run Outs, Golden Break
- Safety count, Safety success, Safety success %
- Fouls, Scratch, Missed easy shots, Position errors
- Kicks, Banks, Jump shots, Combo shots, Carom shots — **all live**.

### 3.3 Cue Ball

- Stop shots, Draw shots, Follow shots, Side spin usage, Position quality distribution — **live**.

### 3.4 Mental

- Confidence, Focus, Pressure, Tilt moments, Composure — **live** (Player State snapshot).

### 3.5 Physical

- Sleep, Fatigue, Energy, Eye condition — **live**.

### 3.6 Equipment

- Cue, Shaft, Tip, Tip hardness, Chalk — **live** (RFC-302 snapshot).

### 3.7 AI Analysis (auto-generated by `MatchReviewEngine`)

- Strengths, Weaknesses, Biggest mistakes, Most improved skill, Suggested drills, Related knowledge articles, Recommended learning path — **all live**.

### 3.8 Match Timeline

- Per-rack events (break, break-and-run, safety exchange, miss, turning point, timeout, final rack).

### 3.9 Statistics

- `LocalMatchRepository.getPlayerAggregates()` updates player-level totals.
- Skill ratings feed the AI Coach profile (left as future hook).

## 4. Architecture

| Constraint | How it is met |
|------------|---------------|
| No hardcoded persistence | All data is read from `IMatchRepository`. |
| Repository abstraction | `IMatchRepository` with `LocalMatchRepository` impl. |
| Offline-first | `SharedPreferences` via `LocalStorageService.prefs`. |
| Supabase-ready | Future `SupabaseMatchRepository` only swaps the implementation. |
| AI analysis pipeline | `MatchReviewEngine.generateAnalysis(matchId)` is side-effect-free and deterministic from current match data. |
